## 2. Мета

Python-пакет читає CSV через csv.DictReader, перетворює поля на типізовані значення, будує звіт
за списками, словниками й множинами та записує детермінований текстовий файл. Помилки — DataError
з номером рядка й першопричиною; поведінку перевіряє pytest.

## 3. Формат CSV і параметр відбору

| Поле | Тип | Правило |
|------|-----|---------|
| ticket | int | > 0 |
| client | str | непорожнє, зайві пробіли прибираються |
| device | str | тип пристрою, непорожнє |
| received | date | ISO YYYY-MM-DD |
| completed | date | ISO, пізніше за received |
| price | float | скінченне, ≥ 0 (0 — гарантійний ремонт) |

Похідне поле `days = completed − received`. Ремонт у роботі на дату d, якщо received ≤ d < completed.
reference_date = 2026-01-03 (параметр `--reference-date`).

## 11. Відповіді на контрольні питання

**1. Яку роль виконує pyproject.toml у Python-проєкті?**

Це єдиний опис проєкту: система збирання (setuptools), назва kzp-lab06, версія 6.0.0, мінімальна версія Python, залежності й група dev (pytest, ruff, build), команда kzp-lab06 і налаштування pytest та ruff. З нього pip встановлює пакет, а build збирає wheel.

**2. Навіщо створюється віртуальне середовище?**

Воно ізолює пакети проєкту від системного Python та інших проєктів: версії pytest і ruff у .venv не впливають на інші програми, а середовище відтворюється командою python -m pip install -e ".[dev]". Каталог .venv не потрапляє в репозиторій.

**3. Чому CSV-файл відкривається з newline=""?**

Тоді модуль csv сам розпізнає роздільники рядків: \r\n у файлі з Windows і перенесення рядка всередині поля в лапках обробляються правильно. Без цього текстовий режим перетворив би роздільники до того, як їх побачить csv.

**4. Які типи повертає csv.DictReader без додаткового перетворення?**

Кожен рядок — словник {назва стовпця: рядок}; відсутні значення — None, зайві — список під ключем None. Числа й дати лишаються текстом, тому loader перетворює ticket на int, received і completed на date, price на float.

**5. Чому split(",") не є коректним CSV-парсером?**

Він ділить і по комі всередині лапок: "Іваненко, Петро" стане двома полями, а подвоєні лапки ("") лишаться в тексті. Також split працює з одним фізичним рядком, а поле в лапках може містити перенесення рядка.

**6. Як відрізняються список, словник і множина?**

Список зберігає порядок і повтори (ремонти в порядку файла), словник зіставляє ключ зі значенням (тип пристрою → кількість ремонтів), множина зберігає лише унікальні елементи без гарантованого порядку (клієнти без повторів: Коваль Оксана рахується один раз).

**7. Коли comprehension робить код зрозумілішим, а коли краще використати цикл?**

Comprehension добрий для одного простого відбору або перетворення: [r for r in records if in_work(r, d)], {r["client"] for r in records}. Для накопичення (лічильники за типом пристрою) чи кількох умов зрозуміліший і швидший звичайний цикл — він проходить записи один раз.

**8. Що містять *args і **kwargs усередині функції?**

*args — кортеж додаткових позиційних аргументів, **kwargs — словник додаткових іменованих. У make_summary(records, "days", "price", price="Виторг") metrics == ("days", "price"), а labels == {"price": "Виторг"}.

**9. Чому змінний об'єкт небезпечний як значення за замовчуванням?**

Значення за замовчуванням обчислюється один раз під час оголошення функції, тож список чи словник спільний для всіх викликів і накопичує зміни. Тому в make_summary типове значення — незмінне число minimum_days=1.

**10. Як raise ... from error зберігає першопричину?**

Початковий виняток записується в атрибут __cause__ нового DataError, а traceback показує обидва з поясненням «The above exception was the direct cause». Тести перевіряють, що причина хибного числа — ValueError, відсутнього файла — OSError, не-UTF-8 — UnicodeDecodeError.

**11. Чому завантаження, аналіз і запис звіту розділяються на модулі?**

Кожну частину можна зрозуміти, тестувати й змінювати окремо: analysis перевіряється на списках без файлів, reporting — без CSV, loader — без звіту, а cli лише з'єднує їх і обробляє коди завершення.

**12. Яку гарантію дає with під час роботи з файлом?**

Файл закривається після виходу з блоку навіть у разі винятку (менеджер контексту викликає __exit__), тому дані дописуються на диск, а дескриптор не «висить».

**13. Чому звіт має формуватися в детермінованому порядку?**

Однакові дані мають давати однаковий текст на будь-якій ОС і за будь-якого порядку рядків, інакше не можна порівняти звіт з еталоном reports/summary.txt у тестах і CI. Тому ремонти впорядковано за квитанцією, типи й клієнти — за українським алфавітом, числа мають два знаки.

**14. Які випадки повинні бути перевірені для порожнього CSV?**

Файл лише із заголовком (коректний порожній вхід, звіт з нулями, код 0), файл 0 байтів (немає заголовка — помилка), порожній результат кожної функції аналізу та порожній відбір для дати без ремонтів у роботі.

**15. Чим тест поведінки відрізняється від перевірки внутрішньої реалізації?**

Тест поведінки перевіряє результат для заданого входу (текст звіту, код завершення, виняток) і не ламається, якщо цикл замінити comprehension. Перевірка реалізації залежить від внутрішніх змінних і падає за будь-якого рефакторингу.

**16. Які файли знаходить pytest?**

У каталозі testpaths (tests) — файли test_*.py або *_test.py, у них функції test_* і методи test_* класів Test* без __init__. Фікстури зі спільного conftest.py доступні всім тестам.

**17. Які перевірки виконує ruff?**

ruff check шукає помилки та порушення стилю за вибраними правилами (E, W — pycodestyle, F — pyflakes, B — bugbear, UP — сучасний синтаксис), ruff format --check перевіряє форматування без зміни файлів.

**18. Які коди завершення має CLI для успіху та очікуваної помилки?**

0 — звіт записано; 2 — помилка вхідних даних або аргументів (повідомлення в stderr, звіт не створюється); 3 — звіт не вдалося записати (наприклад, шлях є каталогом).

**19. Чому в CI запускаються і тести, і аналізатор, і пакетування?**

Вони перевіряють різне: pytest — поведінку, ruff — якість і стиль коду, build та встановлення wheel у чисте середовище — що пакет справді збирається, має всі модулі й запускається як команда на кожній ОС.

**20. Які дані та результати потрібно задекларувати в REPORT?**

Формат CSV і приклад входу, значення reference_date, повний текст звіту, повідомлення про помилки й коди завершення, команди та результати pytest, ruff, wheel і CI, Issues і PR, використання ШІ.
